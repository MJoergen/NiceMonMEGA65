# Compared with the emulator

The goal is a MEGA65 that runs NICE programs as `niceemu`, the emulator in
`nice_cpu/emulator`, runs them. **It is close, but not there yet.** The
core and nice_cpu's devices behave as in the emulator, and so does the
address map, apart from the size of the memory and the registers at
`0xFFFFFF80`–`9F`, where the emulator has memory. The debug link reads
back what the emulator prints after a halt. `tools/run.py` runs a program
on the board and prints what `niceemu` prints for it, so the two can be
compared (see
[Comparing with the emulator](../tools/README.md#comparing-with-the-emulator)).

## What does not match

- The emulator has no ROM, so it has no monitor and no dispatch table
  at `0x0000` until the monitor is joined there:
  `cat monitor/build/monitor.bin prog.bin` runs a program at `0x8000`
  under it, with `r` in the input
  ([PROGRAMMING.md](PROGRAMMING.md#three-levels)). A program at 0 runs
  the same on both, as the tools hide the board's ROM.
- The memory is 128K words on the MEGA65 and 64K on the Nexys4DDR, not
  2³². A program, its data, and its stack must fit. `0xFFFFFF9E` reads
  the number of words on a board, and 0 in the emulator.
- The Nexys4DDR's devices at `0xFFFFFF90`–`96`, and the I2C master at
  `0xFFFFFF97`–`9D`, the size of the RAM at `0xFFFFFF9E`, and the UART's
  baud rate at `0xFFFFFF9F` of every board, are not in the emulator. The network station at `0xFFFFFFB0`
  is in both, but the emulator's counts read 0, and its `NET_STATUS`
  follows `--link`.
- The port for Ethernet frames at `0xFFFFFFC0`–`CF` is in both, but the
  emulator's frames come from a file or a socket, at the writes that
  enable the port and send, and the board's from the network, whenever
  they come.
- An instruction fetch from the fonts at `0xFFFE0000`–`3FFF` reads the
  RAM that they alias, where the emulator fetches the fonts' words.
- `--max-steps` has no equivalent: `run.py` has `--timeout SEC`, which
  prints no registers.
- `--trace`, `--stack`, `--irq`, `--nmi`, `--color`, `--invert-fg`,
  `--no-font`, and `--no-timer-irq` are not available in `run.py`.

The other rows below say "Mostly" or "Yes, but", and have their caveats in
the Notes column.

## The table

emulator: the reserved words, the screen, the console input, the input
FIFO, the ROM, and the aliasing. The rows below that it covers are marked
"([nice_cpu's SYSTEM.md §8](https://github.com/MJoergen/nice_cpu/blob/main/doc/SYSTEM.md#8-systems-built-on-the-fpga-core))".

So a program that fits in the board's RAM prints the same under `run.py`, which
paces its input. Typed by hand, its input must not fall more than 2048
bytes behind. The C example `examples/primes.c` is one, except for the
cycles that it prints.
